## 实施方案：5 轮迭代修复

### 第 1 轮：修复严重问题（C1-C7）

#### 1.1 修复 C1 — settings_dialog.py model_dump() 错误
- **文件**: `hyperbrain/ui/settings_dialog.py:926`
- **改法**: 将 `self._config.model_dump()` 改为 `from dataclasses import asdict; asdict(self._config)`
- **原因**: Config 是 dataclass 不是 Pydantic 模型，没有 `model_dump()` 方法
- **验证**: 导出配置按钮不再报错

#### 1.2 修复 C2 — vector_store.py 暴力搜索未过滤已删除向量
- **文件**: `hyperbrain/database/vector_store.py:142-163`
- **改法**: 在 `_brute_force_search()` 循环内添加 `if self.metadata[i].get("deleted"): continue`
- **原因**: `delete()` 方法仅标记 `metadata[idx]["deleted"] = True`，但搜索未检查此标记
- **验证**: 删除记忆后检索不再返回该记忆

#### 1.3 修复 C3 — model_manager.py 降级修改全局 config
- **文件**: `hyperbrain/models/model_manager.py:621-625`
- **改法**: 移除 `cfg.ollama_model = target_model.model_name` 这行对全局 config 的修改；改为在 model_manager 内部用 `self._active_model_name` 跟踪当前激活模型
- **原因**: 降级是临时行为，不应污染全局配置；否则设置界面显示被篡改，config 持久化写入错误值
- **验证**: 降级后 config.yaml 中的 ollama_model 不变

#### 1.4 修复 C4 — memory_manager.py 使用随机 embedding
- **文件**: `hyperbrain/layers/memory/memory_manager.py:522`
- **改法**: 将 `generate_random_embedding(self.vector_dim)` 改为 `generate_text_embedding(self._extract_text_for_embedding(chunk.content), self.vector_dim)`
- **原因**: 巩固记忆时使用随机向量导致语义搜索完全失效（项目记忆中记录的已知 bug）
- **验证**: 巩固后的记忆可通过语义搜索检索到

#### 1.5 修复 C5 — ollama_model.py 使用旧 embedding 端点
- **文件**: `hyperbrain/models/ollama_model.py:844`
- **改法**: 将 `/api/embeddings` 改为 `/api/embed`，同时适配响应格式（新端点返回 `{"embeddings": [...]}` 列表格式）
- **原因**: Ollama 新版本已弃用 `/api/embeddings`，使用 `/api/embed`
- **验证**: embedding 生成正常工作

#### 1.6 修复 C6 — evolution ModuleConnection 缺少 target_module
- **文件**: `hyperbrain/layers/evolution/architecture_evolution.py`
- **改法**: 排查 `evolve_architecture()` 调用链中所有 ModuleConnection 创建点；在 `optimize_connections()` 和 `evolve_architecture()` 中添加防御性检查，确保所有连接都有 target_module；如果连接的 target_module 对应模块已被移除，则跳过该连接
- **原因**: 错误日志显示架构进化阶段创建 ModuleConnection 时缺少 target_module 字段
- **验证**: 架构进化阶段不再报错

#### 1.7 修复 C7 — test_memory.py 测试失败
- **文件**: `hyperbrain/tests/test_memory.py:22,27`
- **改法**: 适配当前 MemoryItem.content 的实际类型（可能是 dict 而非 string）；在测试中使用临时数据库避免历史数据干扰
- **原因**: 测试期望 content 是字符串，但实际实现中 content 可能是 dict（含 key_info/text 等字段）
- **验证**: test_store_and_retrieve 测试通过

### 第 2 轮：修复中等问题（M1-M5）

#### 2.1 修复 M1 — config.yaml openai_base_url 类型不一致
- **文件**: `config.yaml:103`
- **改法**: `openai_base_url: null` → `openai_base_url: ""`
- **原因**: Config 类定义 `openai_base_url: str = ""`，YAML 中 null 会导致类型不一致

#### 2.2 修复 M2 — config.yaml 模型配置混乱
- **文件**: `config.yaml:88-110`
- **改法**: 
  - 确认 `minimax-m3:cloud` 是否为有效的本地 Ollama 模型名
  - fallback_models 中移除与主模型相同的条目
  - 确保 default_model、ollama_model、fallback_models 逻辑一致
- **原因**: fallback 链第一个就是主模型本身，降级无意义

#### 2.3 修复 M3 — asyncio.iscoroutinefunction 弃用
- **文件**: `hyperbrain/models/error_handler.py:536`
- **改法**: `asyncio.iscoroutinefunction(func)` → `inspect.iscoroutinefunction(func)`，添加 `import inspect`
- **原因**: Python 3.14 弃用 `asyncio.iscoroutinefunction`，Python 3.16 将移除

#### 2.4 修复 M4 — with_retry 熔断器状态不共享
- **文件**: `hyperbrain/models/error_handler.py`
- **改法**: 将 `handler = ErrorHandler()` 改为使用模块级单例 `_global_error_handler = ErrorHandler()`，或使用类变量
- **原因**: 每次调用创建新实例导致熔断器错误计数无法累积

#### 2.5 修复 M5 — scheduler.py _priority_select 副作用
- **文件**: `hyperbrain/models/scheduler.py`
- **改法**: `instances.sort(...)` → `sorted_instances = sorted(instances, ...)`
- **原因**: 直接修改入参列表，调用方可能不期望列表被修改

### 第 3 轮：修复轻微问题（L1-L4）

#### 3.1 修复 L1 — chat_widget.py 代码块正则
- **文件**: `hyperbrain/ui/chat_widget.py:307`
- **改法**: `r'```(\w+)?\n(.*?)```'` → `r'```(\w+)?\n?(.*?)```'`（`\n` 改为 `\n?`）
- **原因**: 单行代码块 `` ```code``` `` 无换行，正则不匹配

#### 3.2 修复 L2 — conftest.py 弃用 event_loop fixture
- **文件**: `hyperbrain/tests/conftest.py:18-22`
- **改法**: 移除自定义 `event_loop` fixture，使用 pytest-asyncio 默认行为；或使用 `pytest_asyncio.fixture`
- **原因**: `asyncio.get_event_loop_policy().new_event_loop()` 在新版 pytest-asyncio 中已弃用

#### 3.3 修复 L3 — 注册 slow marker
- **文件**: `pytest.ini`（根目录）
- **改法**: 添加 `markers = slow: marks tests as slow (deselect with -m "not slow")`
- **原因**: `hyperbrain/tests/` 中使用了 `@pytest.mark.slow` 但根 pytest.ini 未注册

#### 3.4 修复 L4 — nudge_jobs.py 访问私有方法
- **文件**: `hyperbrain/hermes/nudge/nudge_jobs.py:87,106`
- **改法**: 在 `SQLiteManager` 中添加公共方法（如 `get_connection()` 或专门的查询方法），替换 `brain.db._get_connection()`
- **原因**: 直接访问私有方法破坏封装

## 假设与决策

1. **Python 环境**: 使用 `C:\Python314\python.exe`（venv 损坏，不修复 venv，直接用系统 Python）
2. **慢测试**: `test_performance.py` 和 `test_stability.py` 中的 `@pytest.mark.slow` 测试默认跳过，仅在第 5 轮选择性运行
3. **config.yaml 模型名**: 假设 `minimax-m3:cloud` 是用户有意配置的本地 Ollama 模型名，不擅自更改模型名，仅修复 fallback 链逻辑
4. **测试修复策略**: 优先修复实现代码的 bug，只有当测试期望与正确行为不符时才修改测试
5. **不重构**: 仅修复 bug，不做架构重构或功能增强
6. **不修改 venv**: venv 损坏是环境问题，不在代码修复范围内
